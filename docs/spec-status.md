# Сверка со спецификацией 2.0

## Исходное состояние

В репозитории был первый CLI-срез: авторизация, список диалогов, прямой GetHistory,
SQLite/WAL, курсор, resume и JSONL. Не было очереди медиа, дополнительных форматов,
API/worker, веб-панели и Telegram-бота.

## Реализовано

| Область | Реализация |
| --- | --- |
| Общее ядро | TelegramTransport, ExportEngine, ExportService, SessionManager, публичный `tgx_core` |
| Авторизация | Телефон, код, 2FA, QR, профили, переиспользование сессий, явные состояния входа |
| Приватные каналы | Канонические и внутренние ID, entity cache и диалоги с access_hash, общий парсер Telegram-ссылок |
| Приглашения | Проверка существующего доступа без автоматического вступления |
| Диагностика | Раздельные GetHistory/GetMessages/медиа-пробы, точные RPC-ошибки, noforwards как свойство |
| Сканирование | direct/compatibility/recovery/diagnostic, ограниченные страницы, контроль курсора и верхней границы |
| Восстановление | Атомарная запись страницы и курсора, resume, конечные retries соединения, FloodWait/retry_after |
| Модели | Сущности форматирования с типами, подпись, пересылка, reply, реакции, edit_date, служебные действия |
| Изменения | Повторное сканирование обновляет сообщения и сохраняет наблюдённую предыдущую версию |
| Хранилище | SQLite/WAL, Alembic-миграция экспериментальной БД, уникальность account/peer/message, отдельные job_messages |
| Медиа | Отдельная bounded queue, параллельность, retry, обновление file_reference, размеры, SHA-256, временный файл |
| Форматы | JSONL, JSON, TXT, CSV с защитой от формул, SQLite, HTML со страницами, streaming zstd |
| Импорт | Потоковый JSONL и Desktop JSON, объединение по составному ключу, provenance |
| Режимы | full/text/media/range/incremental/reconcile/recovery и проверка архива |
| Задания | Очередь, pause/resume/cancel; UI отменяет с удалением и удаляет завершённые задания |
| API и Web | Защита ключом владельца, фоновый worker, SSE, мобильная панель, подписанные скачивания |
| Безопасность | SessionGuard, закрытые файлы, опциональное шифрование сессий, выход с очисткой данных входа |
| Развёртывание | Локальный CLI/API, Docker/SQLite, опциональный домен/Caddy/HTTPS, отдельный bot, systemd |
| Бот | aiogram 3, allowlist, управление общими заданиями, файлы и временные ссылки |
| Сборки | Wheel/sdist, Windows standalone, CI для нескольких ОС и архитектур контейнера |

## Проверено фактически

- Авторизация реального аккаунта через веб-панель; получение 322 доступных диалогов.
- Реальный приватный канал: 3 671 сообщение, 37 страниц, готовые JSONL и TXT.
- Синтаксис/идентичность/порядок JSONL, количество сообщений, SHA-256, целостность TXT-манифеста.
- Скачанный `messages.txt` совпадает с серверным TXT по SHA-256.
- Синтетические 50, 1 000, 10 000, 100 000 и 1 000 000 сообщений; максимальный рабочий набор
  в нагрузочном прогоне — 44 908 544 байта, без роста пропорционально количеству сообщений.
- Unit/integration-тесты охватывают resume, разрывы соединения, FloodWait, заполнение диска,
  повреждённый checkpoint, медиа/хеши, форматы, API, миграцию, авторизацию, ID и управление заданиями.

## NOT VERIFIED

Реальная загрузка всего разнообразия защищённых Telegram-медиа, сравнение с Telegram Desktop/AyuGram,
запуск Docker/Caddy и сертификата реального домена, настоящий Telegram-бот, macOS/Linux/Termux/iOS,
принудительное выключение ОС и перезапуск контейнера. Фальшивое доказательство этих сценариев отсутствует.

## Необязательные последующие расширения из спеки

TDLib как независимый второй транспорт, PostgreSQL для многопользовательской установки,
раздельный worker-процесс с несколькими владельцами, нативные приложения Android/iOS и GUI macOS.
Текущая серверная конфигурация — один владелец, один bounded worker и SQLite.
Recovery проверяет доступные альтернативные запросы, но не доказывает существование удалённых/скрытых сообщений.
